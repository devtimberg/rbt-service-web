# Заказ запчасти — MVP

Макет: [Заказать запчасть — MVP](https://www.figma.com/design/McTZS5CWwqW9iYsjhonNMz/?node-id=499-573).

`/parts/request` открыт как шторка: телефон и email обязательны; партномер (до 50 символов) и комментарий (до 255) необязательны. Ошибки проверяет zod. Чек обновляется при вводе; номер появляется после ответа мутации. На мобильном основная кнопка закреплена в нижней панели, при экранной клавиатуре панель скрыта.

Черновик хранится отдельно от вызова мастера в `sessionStorage`, ключ `rbt:parts-request:draft:v1`. При перезагрузке восстанавливается, после успеха или подтверждённого ухода удаляется. Применяется существующий NavigationGuard (ADR 0014). Поздний ответ после ухода не меняет экран.

**Отправка через customer API:** RTK Query → `POST /api/customer/spare-part-requests` (Route Handler Next.js) → `POST ${API_INTERNAL_URL}/customer/spare-part-requests`. Контракт: [Swagger customer](https://test.rbt74.ru/api/swagger-ui/index.html?urls.primaryName=customer#/Заявки%20на%20запчасти/create), проверен 2026-11-06. Телефон из поля переводится в `+7…`, пустые необязательные поля не отправляются. `requestCode` отображается как номер заявки. API не возвращает дату: в чеке используется время получения успешного ответа, а не дата создания на сервере.

`409 duplicate` означает повторную заявку с тем же телефоном, email или IP за 15 минут; форма показывает отдельное сообщение и сохраняет черновик. Ошибки `attrErrors` привязываются к полям через react-hook-form; английские сообщения бэкенда заменяются русскими. Сетевой сбой и некорректный успешный ответ не переключают форму на успех. Автоматического повтора POST нет.

На сервере проверяются тело и IP. Внешний прокси обязан перезаписывать `X-Real-IP` реальным адресом клиента и закрывать прямой доступ к Next.js в обход прокси. Next передаёт IP заголовком `X-Real-IP`; `X-Forwarded-For` не используется. При прямом локальном запуске (`make dev` и `make start`) на localhost, 127.0.0.1 или [::1] используется `127.0.0.1`. Локальный адрес определяется по Host, поскольку Next может подставлять внутренний hostname в request.url. Для публичного Host без IP запрос отклоняется. В OpenAPI параметр ошибочно описан как query при описании заголовка в тексте операции; используется заголовок согласно тексту контракта. Нужно подтвердить его обработку при приёмке на стенде.

`API_INTERNAL_URL` — базовый адрес вместе с `/api`, например `https://test.rbt74.ru/api`; он читается только сервером. Авторизация не добавляется (ADR 0010): проверка пустого запроса на тестовом API дала `400 invalid` с `attrErrors`, без токена. Успешная отправка реальной заявки на стенд при разработке интеграции не выполнялась.

Используются существующие примитивы и общие изображения из `public/images/receipt-printer`; наклейка «Дело техники» из макета сохранена там же в `sticker-parts-request.webp`. Композиция сцены живёт в новом слайсе страницы: код и стили вызова мастера не менялись. Другие разделы остаются закрыты.
