# 0008. Без голых HTML-элементов вне shared/ui

Дата: 2026-10-15
Статус: accepted

## Контекст

Эталон rbt-web запрещает верстать на голых HTML-элементах: разметка собирается из примитивов `shared/ui`. Без запрета в страницах и виджетах накапливаются одноразовые `div`, `button` и `input` с повторяющимися классами, а доступность и семантика зависят от внимательности автора. Примитивы проекта (0005) уже покрывают нужные теги.

## Решение

Правило Oxlint `react/forbid-elements` в блоке `lint` файла `vite.config.ts` запрещает голые элементы (`div`, `section`, `button`, `input`, `a`, `h1`–`h6`, `p`, `span`, `ul`, `img`, `svg`, `form`, `label` и др.). Для каждого в сообщении указан примитив замены (`forbiddenElements`).

Исключения:

- `src/shared/ui/**`: примитивы по определению пишутся на HTML;
- `**/*.test.tsx`: тесты рендерят заглушки слотов;
- `html`, `head`, `body` в `routes/__root.tsx` не входят в список запрещённых, это каркас документа.

Если нужного примитива нет, он добавляется в `shared/ui` (и в витрину `/_dev/ui`), а не заменяется точечным отключением правила.

## Последствия

- Вёрстка единообразна, семантику задают `as`, `level`, `variant` примитивов.
- Нарушение даёт красный `make lint` и pre-commit; хуки не обходим.
- Расширение набора примитивов становится обязательной частью задачи, если их не хватает.
- Список запрещённых элементов поддерживается вручную при появлении новых тегов в примитивах.
