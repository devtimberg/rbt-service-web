# 0009. Переход на Next.js, CSS Modules, RTK Query и react-hook-form вслед за rbt-web

Дата: 2026-10-28
Статус: accepted, фазы 0–2 выполнены, фаза 3 впереди ([план](../nextjs-migration.md))
Заменяет: [0001](0001-tanstack-start.md)
Частично заменяет: [0002](0002-vite-plus.md), [0005](0005-own-ui-primitives.md), [0006](0006-sheets-via-static-data.md), [0007](0007-zustand-temporary.md)

## Контекст

TanStack Start выбран в [0001](0001-tanstack-start.md) ради одного стека с rbt-web. 2026-10-25 rbt-web перешёл на Next.js (App Router), CSS Modules вместо Tailwind, RTK Query для данных сервера и react-hook-form для форм (ADR 0022 репозитория rbt-web, `docs/adr/0022-nextjs-css-modules-rtk-query.md`). Причина 0001 осталась, сменилась цель: чтобы стек совпадал с rbt-web, переходим вслед за ним.

## Решение

Принимаем ADR 0022 rbt-web целиком: фреймворк, размещение маршрутов, модель данных, стили, формы и инструменты оттуда, без пересказа здесь. Ниже только то, что касается этого репозитория.

Порядок работ повторяет план rbt-web (`docs/nextjs-migration.md` там): оси меняются по отдельности, после каждой фазы приложение работает и `make check` зелёный.

1. **Фаза 0.** Этот ADR, план, `make style-check` (сравнение вёрстки двух сборок, перенесён из rbt-web) и эталон текущей вёрстки.
2. **Фаза 1, в `main` на текущем стеке.** CSS Modules и react-hook-form не зависят от фреймворка, Tailwind и модули в Vite работают одновременно. Каждый шаг сверяется `make style-check` с эталоном внутри одного фреймворка, без шума от смены сборщика. Завершается удалением Tailwind и `tailwind-merge`.
3. **Фаза 2, своей веткой.** Маршруты на Next App Router, TanStack Start и Nitro удаляются. К этому моменту стили уже на модулях, которые Next поддерживает без настройки, Tailwind в Next не заводится.
4. **Фаза 3, своей веткой от `main`.** RTK Query вместо TanStack Query: стор на запрос, гидрация по сегментам. Зависит от Next, поэтому последняя.

Что из этого репозитория сохраняется:

- ~~cookie-сессия ([0004](0004-cookie-session.md))~~: авторизация убрана из MVP ([0010](0010-no-auth-in-mvp.md)), переносить нечего;
- FSD ([0003](0003-fsd-and-imports.md)), свои примитивы без Radix и shadcn ([0005](0005-own-ui-primitives.md)), запрет голых HTML-элементов ([0008](0008-no-bare-html-elements.md));
- линт, форматирование, тесты и хуки на Vite+ ([0002](0002-vite-plus.md)).

Открытые вопросы решены отдельными ADR до фазы 2: pnpm с Node 24 ([0011](0011-pnpm-node-24.md), ADR 0021 rbt-web), имена файлов в kebab-case и папка на компонент в `shared/ui` ([0012](0012-kebab-case-filenames-ui-folders.md), ADR 0020 rbt-web).

## Последствия

- 0001 получает статус `superseded by 0009`. Частично заменены: 0002 (сборка и dev через Next с фазы 2), 0005 (Tailwind и `tailwind-merge` уступают CSS Modules и `clsx` в фазе 1), 0006 (механизм шторок через `staticData` заменён в фазе 2 на [0013](0013-sheets-in-next.md)), 0007 (данные сервера уходят в RTK Query в фазе 3; сторы корзины, избранного и истории поиска живут до API). Остальные правила этих ADR действуют, пока их не снимет соответствующая фаза.
- Пока идёт переход, код в `main` может следовать старым ADR. Новых экранов на старом стеке не начинаем, если фаза, которая их перепишет, уже открыта.
- Next.js убран из запрещённого в AGENTS.md.
- Выигрыш: один стек и одни практики с rbt-web, его примитивы и решения переносятся почти без адаптации. Потери из ADR 0022 rbt-web распространяются и сюда: типизированные маршруты и search-параметры TanStack Router заменяют zod-схемы, растёт риск перегруженного HTML от гидрации Redux.
