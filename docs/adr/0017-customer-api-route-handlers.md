# 0017. Customer API через Route Handlers Next.js

Дата: 2026-11-06
Статус: accepted

## Контекст

Появились API создания заявки на запчасти и вызова мастера. `API_INTERNAL_URL` доступен только серверу, а API требует реальный IP от доверенного прокси. Браузерная RTK Query мутация не должна обращаться во внутреннюю сеть и сама выбирать IP для ограничения повторных заявок. Server Actions запрещены ADR 0009, авторизация отсутствует по ADR 0010.

## Решение

Браузерный `apiFetch` обращается к фиксированным Route Handlers Next.js под `/api`. Серверный `apiFetch` использует `API_INTERNAL_URL`. Мутации сущностей получают клиент через `extraArgument` стора, ошибки преобразуются в сериализуемые данные. Корневой `app/api` только экспортирует обработчик из отдельной серверной точки входа сущности. Серверный модуль не экспортируется из клиентского бареля сущности.

Первый обработчик `POST /api/customer/spare-part-requests` проверяет тело по контракту и передаёт `X-Real-IP` из доверенного ingress. Ingress перезаписывает заголовок и исключает прямой внешний доступ к Next.js. Непроверенный `X-Forwarded-For` не используется, без IP на публичном Host отправки нет. Прямой локальный запуск (`make dev` и `make start`) на localhost, 127.0.0.1 или [::1] использует loopback; Host имеет приоритет над внутренним request.url Next. Ответ подтверждает успех только при наличии `requestCode`.

Аналогично подключён `POST /api/customer/requests` для вызова мастера: тело `CreateServiceRequest`, ответ `CreateServiceResponse` с `requestNumber`. Определение адреса клиента вынесено в общий серверный `shared/lib/request-client-ip.ts`; обе мутации используют одинаковые правила прокси и локального запуска.

## Последствия

API остаётся внутри серверной границы, браузеру не нужен CORS. Нет универсального открытого прокси: каждый маршрут явно разрешён и валидируется. Для развёртывания обязательны правильные базовый URL и настройка IP на ingress. POST не повторяется автоматически: после сетевого сбоя создание могло уже произойти. У первой мутации нет SSR-данных; стор на серверный запрос, prefetch и Hydrate добавляются с первым query согласно ADR 0009.

Swagger пока ошибочно описывает `X-Real-IP` как query-параметр при требовании заголовка в тексте; используется заголовок, обработку которого нужно подтвердить при приёмке. Контракт ошибок проверен пустым запросом без создания заявки: `400`, `code=invalid`, `message=null`, `attrErrors`. Для вызова мастера с разрешения заказчика подтверждены реальное создание (`200`, `requestNumber`) и повторная отправка через Next.js (`409 duplicate`). Успешный сценарий заказа запчасти требует отдельной приёмки.
