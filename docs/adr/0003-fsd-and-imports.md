# 0003. Упрощённый FSD и правила импортов

Дата: 2026-10-15
Статус: accepted

## Контекст

После Next.js в проекте были `screens`, `widgets`, `shared/ui/kit` без строгих границ. Нужна предсказуемая структура, одинаковая с rbt-web.

## Решение

Слои `routes → app → pages → widgets → features → entities → shared`, импорт только вниз, слайсы одного слоя друг друга не импортируют. Снаружи слайс доступен только через `index.ts`; в `shared` слайсов нет, только сегменты. Группы слайсов (`features/auth/*`) допустимы без общего `index.ts`. Контроль: `lint/fsd-rules.ts` (Oxlint) и steiger (`bun run lint:fsd`), оба в pre-commit.

## Последствия

- Нарушения границ ловятся автоматически, новый сегмент слайса нужно добавлять в шаблон правил.
- `src/routes` и точки входа Start не относятся к слоям FSD, steiger их игнорирует.
- Блок одной страницы лежит в `pages/<page>/ui` и переезжает в `widgets` при втором использовании.
